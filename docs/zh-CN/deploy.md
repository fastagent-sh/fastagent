# 部署指南

将你的 Agent 上线到任意容器宿主机或无服务器运行时。FastAgent 只在初始化时生成干净、可自由编辑的部署文件，再把实际部署交还给各平台原生 CLI——零锁定、无黑盒。

## 选择部署目标

| 目标平台 | 最适合场景 | 准备文件 | 执行部署 |
| --- | --- | --- | --- |
| **Docker / 任意容器宿主机** | 自托管 VM、Kubernetes、ECS、Cloud Run | `fastagent deploy init docker` | `docker build` / `docker run` |
| **Docker Compose** | 单机 VPS + 持久化卷 | `fastagent deploy init compose` | `docker compose up -d --build` |
| **Fly.io** | 托管单机、空闲休眠 HTTP 服务 | `fastagent deploy init fly` | `fly launch --copy-config --ha=false --no-deploy` → `fly deploy --ha=false` |
| **Railway** | 极简 PaaS + 数据卷 + App Sleeping | `fastagent deploy init railway` | `railway init` → `railway volume add --mount-path /data` → `railway up` |
| **Amazon Bedrock AgentCore** | 每用户独立 MicroVM + Aurora DSQL | `npm i @fastagent-sh/agentcore && fastagent deploy init agentcore` | `npx -y @aws/agentcore@1.0.3 deploy`（见 [AWS AgentCore](agentcore.md)） |

> **单实例单副本：** 单个实例的 SQLite 卷或 PostgreSQL 租约同一时刻仅由一个进程持有。请通过运行多个独立实例实现水平扩展（或使用 [AgentCore](agentcore.md) 自动按用户分配 MicroVM）。

## 部署前检查清单

1. **在本地验证生产构建：**
   ```bash
   fastagent build
   fastagent start --root "$(mktemp -d)" --env-file prod.env
   ```
2. **确保已设置默认模型**：在 `fastagent.config.ts` 中配置 `model`，或在宿主机设置 `FASTAGENT_MODEL`。
3. **准备运行时密钥**：`FASTAGENT_API_KEY`（用于挂载 `/v1`）、模型 API Key、所有 `needs()` 声明的密钥，或部署后通过 [`fastagent login --remote`](remotes.md#远程模型提供商认证) 远程登录。
4. **在 CI 中用 `fastagent deploy check` 设置门禁**：校验 Agent 可正常加载，且构建上下文不会泄漏本地 `.secrets/`、`.env*` 或 `.state/` 文件（`exit 0` 安全、`exit 1` 阻断；支持 `--json`）：
   ```bash
   fastagent deploy check && fly deploy --ha=false
   ```

## Docker

```bash
fastagent deploy init docker
docker build --pull -t my-agent .
docker run -d --name my-agent --restart unless-stopped \
  -v my-agent-data:/data \
  --env-file prod.env \
  -p 8787:8787 \
  my-agent
```

## Docker Compose

```bash
fastagent deploy init compose
```

生成 `Dockerfile`、`.dockerignore` 和 `compose.yml`（挂载 `/data`、读取可选 `prod.env`、配置 `GET /health` 健康检查）。将运行时密钥写入 `prod.env`（已被 `.dockerignore` 排除），然后启动：

```bash
docker compose up -d --build
```

## Fly.io

Fly.io 默认启动两个副本，会导致争抢 `/data` 卷。`fastagent deploy init fly` 生成的 `fly.toml` 默认开启空闲休眠（`auto_stop_machines = "suspend"`、`min_machines_running = 0`）、挂载 `/data` 卷并配置 `GET /health` 探针：

```bash
fastagent deploy init fly
fly launch --copy-config --ha=false --no-deploy
fly secrets set FASTAGENT_API_KEY=<key> <MODEL_API_KEY>=<value>
fly deploy --ha=false
```

由于 Fly Proxy 在没有活跃 HTTP 连接时会休眠机器，请在轮次运行期间保持请求连接（使用带 `wait` 或 `stream: true` 的 `POST /v1/invoke`、`messages.stream` 或带 `wait` 的 `messages.send`）；若依赖“发后即忘”的后台轮次，请将 `min_machines_running` 设为 `1`。

## Railway

```bash
fastagent deploy init railway
```

生成 `Dockerfile`（`EXPOSE 8787`）和 `.dockerignore`，并打印 Railway 操作步骤：

```bash
railway init
railway volume add --mount-path /data
railway variables --set FASTAGENT_API_KEY=<key> --set <MODEL_API_KEY>=<value>
railway up
```

在 Railway 服务设置中保持 **1 个副本**，按需开启 **Serverless (App Sleeping)** 实现空闲休眠，并将健康检查路径设为 `/health`。

## 空闲休眠、定时任务与 Webhook

通过单次 `POST /v1/invoke`（携带 `Idempotency-Key`、可选命名 `conversation` 以及最长 `600` 秒的 `wait` 或 `"stream": true`）来驱动定时任务或事件触发器（Cloud Scheduler、EventBridge、GitHub Actions、Railway Cron、Webhook）。宿主机平台会自动唤醒容器、保持其运行直至轮次结束，并在完成后安全休眠：

```bash
curl -s https://<your-host>/v1/invoke \
  -H "Authorization: Bearer $FASTAGENT_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: daily-$(date +%F)" \
  -d '{"conversation": "daily-digest", "content": "/daily-digest", "whenBusy": "reject", "wait": 300}'
```

## 验证与运维线上实例

```bash
# 保存为命名远程端点（CLI 与 @fastagent-sh/pi-remote 共享）
fastagent remote add prod https://<your-host> --key '$PROD_AGENT_KEY'

# 通过 Agent API 做冒烟测试
fastagent invoke --remote prod "hello"

# 可选：远程完成 OAuth 登录（持久化保存在 /data 或 PostgreSQL）
fastagent login openai-codex --remote prod
```

将 `FASTAGENT_API_KEY` 设为逗号分隔的 `new,old`，待调用方全部切换后再移除 `old`，即可实现零停机密钥轮换。

## 容器细节与文件归属

生成的 `Dockerfile` 会安装依赖、执行 `fastagent build`、暴露 `8787` 端口、设置 `FASTAGENT_DEPLOYED=1`、`FASTAGENT_NAME=<agent>` 与 `FASTAGENT_ROOT=/data`，并以 `fastagent start` 启动。如需在容器内启用 OS 沙箱，请先将 `@fastagent-sh/harness-dsh` 安装到 `package.json`，再设置 `harness: "dsh"`（或 `FASTAGENT_HARNESS=dsh` 及 `FASTAGENT_SANDBOX`）。当启用 `bash` 且开启沙箱时，`harness: "dsh"` 会在启动阶段主动校验 OS 沙箱可用性并在不可用时快速失败；生成的 `node:24-slim` Linux 镜像默认通过内置 Landlock 启动器生效（需宿主机 Linux 内核支持 Landlock），如需 `bwrap` 挂载与 PID 命名空间隔离，请在自定义 Dockerfile 中安装 `bubblewrap` 并开启容器 user namespace 权限。

生成的 `.dockerignore` 默认排除 `.secrets/`、`.env`、`*.env`、`.state/`、`.fastagent/` 与 `node_modules`。

- **平台配置文件（`compose.yml`、`fly.toml`、`agentcore/`）** 仅生成一次，之后完全归你所有，绝不覆盖。
- **`Dockerfile` 与 `.dockerignore`** 首行带有 `# Generated by` 标记。删除该行即转为永久手动维护；运行 `fastagent deploy init <target> --force` 仅会重新生成由 FastAgent 托管的文件。

**持久化卷目录布局：**

```text
/data/
├── .state/           # SQLite 会话、持久化凭证与命名对话映射（未用 PostgreSQL 时）
└── .deployment/      # 单写者租约与归属 Agent 标识——切勿删除
```

如需将会话、持久化凭证与命名对话存入托管 PostgreSQL 而非 `/data/.state/`，只需设置 `FASTAGENT_DATABASE_URL`（见[使用 PostgreSQL 存储会话](configuration.md#使用-postgresql-存储会话)）。
